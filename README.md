# 知会 · 校园事件整理

一个可由 Agent 查询和写入的校园事件面板，用于集中保存、整理和查看分散的校园事件。当前版本使用邮箱＋密码登录、SQLite 持久化保存、每人独立且可撤销的 Agent 密钥，不依赖 OpenAI 账号。

使用流程：把事件发给 Agent → Agent 提取标题、摘要、分类和日期并保留原文 → 调用工具入库 → 网页面板自动显示。

已连接 MCP 的电脑端 Agent 还可使用随项目提供的 `zhihui-notices` skill，实时查询事件、读取原文，并把近期安排生成本地 HTML 时间轴。当前优先完善电脑端使用，手机与机器人通道暂缓。

## 快速开始：Windows 本地启动包

适用于 Windows 10 / 11 x64，无需安装 Node.js、npm 或 Docker，也无需云端账号。

仓库源码不包含 `releases/` 和独立部署 ZIP。若从 GitHub 下载源码，请按下方“从源码运行”直接启动，或自行构建启动包；维护者发布后，也可从仓库的 Releases 下载启动包附件。

1. 完整解压 `releases/zhihui-windows-x64.zip`，不要在压缩包内直接运行。
2. 打开“知会本地版”文件夹，双击“启动知会.cmd”，程序会自动打开浏览器。
3. 首次使用注册邮箱账号。使用期间保留启动窗口，停止时双击“停止知会.cmd”，或在启动窗口按 Ctrl+C。

默认使用 `http://127.0.0.1:4173`；端口被占用时自动选择可用端口，并记住本次地址。重复双击会重新打开已经运行的面板，不会再启动一个服务。实际网页和 MCP 地址以启动窗口、面板显示为准。

启动包的账号和事件保存在包内的 `data` 文件夹。它与源码运行目录的数据相互独立，压缩包不包含开发者的账号、事件或密钥。旧事件可通过 JSON 备份导入；账号和 Agent 密钥需要重新创建，原有 Codex 连接不会自动切换。完整备份或搬家前先停止程序，再复制整个 `data` 文件夹。

维护者可在 PowerShell 7 中构建启动包（使用启动包不需要 PowerShell 7）：

```powershell
pwsh -NoProfile -File standalone/build-portable.ps1
```

首次构建会从 Node.js 官方下载固定版本的 Windows x64 运行环境并核对 SHA256，包含运行环境的开源许可；产物为 `releases/zhihui-windows-x64.zip` 和同名 `.sha256` 校验文件。解压后的程序运行不需要联网下载依赖。

启动包测试（先构建，测试只在 Windows 且存在压缩包时运行）：

```powershell
node --test standalone/portable.test.mjs
```

测试会从实际压缩包解压，在带中文和空格的路径运行 CMD 入口，验证端口避让、重复启动、注册、MCP 导入、停止与重启后数据保留，使用临时目录。

## 从源码运行：独立邮箱版

Windows 调试时，直接双击源码根目录的 **“启动调试.cmd”**，会自动打开浏览器。无需安装 npm 依赖或执行前端构建；优先使用项目已缓存的 Node.js 24，没有缓存时检查本机 Node.js（需 24 或以上）。

使用期间保留启动窗口，关闭窗口或按 Ctrl+C 即可停止。修改源码后，关闭原启动窗口，再双击“启动调试.cmd”即可。

源码启动直接运行网站服务，默认打开 `http://127.0.0.1:4173`，数据保存在本目录的 `data/notice-inbox.sqlite`，保留已有账号和事件。它与解压启动包的数据独立。

也可在项目根目录手动运行（需要 Node.js 24）：

```powershell
node standalone/server.mjs
```

打开 [本地登录页](http://127.0.0.1:4173/login)，注册自己的邮箱账号，密码为 12—128 个字符。没有默认账号；目前邮箱只作为登录名，不发送验证邮件。

也可以在 Windows 右键 `standalone/start.ps1`，选择“使用 PowerShell 运行”。关闭运行程序的终端会停止服务，再次启动后原有账号和事件仍保留。

默认本地地址仅供这台电脑直接访问。工具若在其他机器执行，则需要本机执行桥或可访问的服务地址。

## 自定义事件分类

在侧边栏“事件分类”右侧点击“管理”，可新增、重命名和删除分类，按账号保存，重启后保留。每个名称为 1—30 个字符，最多 30 个分类；默认分类也可调整。“其他事件”作为保留分类，不能重命名或删除。

重命名会同步更新已有事件及日程；删除分类会将其中的事件及日程移到“其他事件”，保留原文、编号和收藏。事件表单和筛选栏同步使用当前分类，JSON 备份会带上分类（包括空分类），导入时恢复缺少的分类。

已有“日程”“课程”分类继续保留，课程仍有独立默认归类。表单类型为“事件／课程”，与一次性／周期性彼此独立：每周锻炼可设为重复事件，一次补课也可以是课程。新普通事件默认使用“其他事件”，也可选已有分类；课程使用当前课程默认分类。已有记录可在同一编辑表单切换类型。自定义分类仍可使用；重命名默认分类后后续导入继续跟随，删除后改用“其他事件”。升级时保留已有编号、类型和自定义归类。

每个分类有对应颜色，自定义分类按名称自动生成颜色；“全部事件”的卡片使用同色边条、边框、浅色背景与分类标签，侧栏色点同步对应。

MCP 导入和查询也支持当前账号的分类；当前工具 schema 和查询结果的 `categories` 会给出可用名称。“其他事件”的接口值沿用 `其他通知`，Agent 应使用工具返回的实际值。分类管理通过网页登录会话操作，Agent 密钥不能管理分类；未创建的分类会返回错误，需要先在面板添加。Agent 客户端若缓存了旧分类枚举，请刷新 MCP 工具列表。

## 事件时间表

点击首页“我的收藏”右侧的“事件时间表”卡片，或左侧同名入口，选择未来 7／14／30 天，或填写任意开始、结束日期后点击“查看”。范围包含起止当天，统一按北京时间展示；可只看活动或截止事项，点击事件名称回到对应事件原文。跨天活动与窗口有交集就显示，开始早于窗口时标为“进行中”，并保留真实起止时间。

添加或编辑事件时，可保留零个、一个或多个时间点，每个明确时间点分别选择“不重复”或“每周重复”。日期未知时通常只保存事件，也可保留标题及依据作为待定时间点；待定项日期留空，不能填时分、结束范围或周期规则，不会进入时间表。时分不确定可留空；不能把活动日期填进事件的“截止日期”。Agent 也可通过 MCP 的 `events` 及每项 `recurrence` 录入。已有事件的明确截止日期直接显示，同日已有精确截止事项时不重复显示。

时间表展示所有已记录且有效的时间，包括“资料信息”与“纳入我的安排”。有日期进入时间表不等于已报名或承诺参加；只有明确纳入我的安排，才作为个人排程约束。无日期的事件仍可保存并出现在“全部事件”，不会补造日期。旧事件的活动时间可通过编辑补充；重复导入不会更新旧事件。时间项随事件保存在 SQLite 中，JSON 备份也会保留。

更新后的 skill 可根据事件和用户提供的任务、课表、可用时间，拆解步骤并提出今日／每周计划、说明已知冲突。个人任务、执行计划、完成状态及时间偏好可通过管理工具保存，复盘依据真实状态和修改记录；未实际保存的排程仍标为建议，定时提醒尚未实现。详细流程见 [规划说明](./skills/zhihui-notices/references/planning.md)。

## 个人时间管理与截图课表

**全部事件**统一显示事件和课程，通过分类颜色、类型标签、时间及地点区分。类型筛选可选择事件或课程，重复方式筛选独立选择不重复或每周重复。每个周期系列只占一张卡片，展示重复规则和下一次安排；事件统计也按卡片数计算，不按整个学期展开的课次数计算。点击侧栏“日程”或“课程”可分别查看默认归入对应分类的安排，调整分类后会出现在对应分类。收藏也支持日程和课程系列。

页面顶部“添加事件”直接打开同一个表单，添加普通事件与日程不再分入口。只填标题即可保存，时间、原文、来源及地点均可空；需要时再添加多个时间点、分别设置重复方式，并选择“事件／课程”和“资料信息／纳入我的安排”。已有个人日程也使用这个表单编辑，保留原编号和单次调课规则；旁边的“连接 Agent”用于管理 MCP 连接和密钥。

网页编辑普通事件时会携带读取时的 `expectedUpdatedAt` 检测并发修改；记录已变化时提示重新读取，避免覆盖其他页面或 Agent 的更新。

“资料信息”表示保存活动、公告或备选机会，不会自动占用个人空闲；“纳入我的安排”表示已经决定安排的课程或日程。升级时原普通事件保留为资料信息，原个人日程和课程保留为我的安排，避免改变既有记录的含义。

日程卡片可编辑一次性安排或整个周期系列，也可单独调整／取消某次课程。取消的日程默认隐藏，可显示后恢复；时间表仍按所选日期范围展开每次实际发生的安排，取消或排除的课次不显示。“个人任务”保存待办、进行中、完成和取消状态及执行时段；“时间偏好”保存每天可投入时长、缓冲、作息、学期和节次映射；“计划复盘”按所选日期读取完成、到期、当前逾期和修改历史。预计时长不当作实际学习时间。

让 Agent 管理这些数据时，在“连接 Agent”创建“时间管理”密钥并更新客户端连接；旧密钥不自动获得修改权限。新工具见 [Agent 接入说明](./AGENT_INTEGRATION.md)。安装新版 skill 并刷新工具列表后，可这样使用：

- “把这张课表截图导入知会，保留每门课的周次和单双周。”
- “学期第 1 周从 9 月 7 日开始，这是学校的节次作息，请保存。”
- “我要参加这项比赛，拆成任务，并结合课表安排本周准备时间。”
- “本周三这节课改到周五 16:00—17:40，只改这一次。”
- “报名材料提交了，标为完成。总结一下本周还有哪些没做完。”

截图由 Agent 自身视觉能力识别，程序接收结构化数据并保存转写依据。课程通过 `import_events` 并明确 `recordType: "course"` 导入，省略分类时归到当前课程默认分类（初始为“课程”），在“全部事件”和对应分类查看同一份数据，无需再通过 `import_notices` 复制。已有明确的学期和节次设置时直接导入；缺少学期第 1 周日期、节次实际时刻或截图字迹不清时，Agent 会集中核对关键缺口，不猜测日期或上课时间。

周期规则以起算日期所在周的周一为第 1 周，可指定每周星期、周间隔、适用周次和排除日期，且有明确结束日期。时间表在选定范围（单次最多 366 天，含首尾日）逐次展开，不会在非适用周或学期结束后继续显示。假期不自动排除，须有明确日期。

仅一次调课会排除原课次并新建一次性替代事件；仅一次停课只排除原课次；整个系列的编辑会明确区分。取消系列和任务均可恢复。重复导入原课表不会覆盖已经做过的调课、停课或取消操作。

所有数据仍在本地 SQLite、按账号隔离。面板“导出原文”仅备份普通事件及其原文，不包含个人日程、课表和任务；完整备份日程、任务、课表、偏好和历史时，停止服务后复制整个 `data` 文件夹。程序不运行后台自动排程或定时提醒；Agent 根据实时数据提出计划，并按用户要求保存调整。

## 连接 Agent

1. 登录面板，点击“连接 Agent”，按需选择“仅导入”“仅查询”“查询＋导入”或“时间管理”，创建并复制密钥。完整密钥只显示一次。
2. 在支持外部工具的 Agent 中配置以下任一入口，认证头为 `Authorization: Bearer 你的密钥`。
3. 把事件发给 Agent 要求保存，或提问“未来七天有哪些事件截止？”“把这条事件的原文发给我”。

| 接入方式 | 本地地址 | 用途 |
|---|---|---|
| MCP（Streamable HTTP） | `http://127.0.0.1:4173/mcp` | 按授权提供 `import_notices`、`list_notices`、`get_notice` |
| HTTP | `http://127.0.0.1:4173/api/agent/notices` | POST 导入，GET 查询，GET `/api/agent/notices/事件编号` 读取原文 |

部署后将地址替换为自己的 HTTPS 域名。远程 Agent 的 `127.0.0.1` 指向它自己的运行环境，不能用这个地址连接你的电脑。

旧密钥保持仅导入权限；查询需要新建“仅查询”或“查询＋导入”密钥。时间管理密钥可创建和调整任务、课程与偏好，也可更新事件时间事项；其他密钥不能修改。事件原文修改及删除不开放给 Agent。密钥有效期 90 天，可在面板撤销。其他使用者仍需配置自己的地址和密钥；客户端如果有工具白名单，也需按新密钥的权限更新。不要把真实密钥写进源码、URL 或事件正文。

面板每 5 秒检查新事件，回到页面时也会刷新。只有工具返回成功结果和保存编号，才代表事件已保存。参数、示例与权限边界见 [Agent 接入说明](./AGENT_INTEGRATION.md)。

本站不内置大模型、OCR、网页抓取或语音识别。整理、截图识别、链接读取和语音转写由调用方 Agent 负责。连小理接入与事件导入已由用户实测通过。

### 让 Agent 自动配置 MCP 的提示词

适用于能够读写本机客户端配置的 Agent。先启动知会，在面板点击“连接 Agent”，按需选择权限并复制 MCP 地址和密钥，再替换下方占位内容；也可在创建密钥后直接点击“复制配置提示词”。既要查事件也要保存时选择“查询＋导入”。启动包可能自动更换端口，请使用面板显示的实际地址。真实密钥只填写到发给受信任 Agent 的消息中，不要写回本 README 或公开仓库。

```text
请帮我把本机运行的“知会”配置为当前 Agent 客户端的 MCP 服务，并实际验证可用性。

服务名称：zhihui_local
服务地址：【粘贴面板显示的 MCP 地址】
传输方式：Streamable HTTP
认证方式：Authorization: Bearer 【粘贴所选权限的密钥】
工具按密钥权限开放，以 tools/list 的当前结果为准。仅导入可保存事件；仅查询可读取事件与时间管理数据；查询＋导入另可保存新事件；时间管理可创建和调整个人任务、课表、偏好及事件时间事项。不得自动扩大旧密钥权限。

请直接完成配置：
1. 识别当前客户端支持的 MCP 配置方式，保留已有配置，只新增或更新 zhihui_local。
2. 优先使用客户端支持的安全凭据方式保存密钥，不在输出中复述密钥，不写进项目源码或提交到 Git。
3. 检查本地知会是否运行，验证 MCP 初始化和工具发现，按发现结果更新本服务的工具白名单。旧密钥只会发现 import_notices，不要尝试自行提升密钥权限。
4. 有导入权限时，调用 import_notices 导入一条“【MCP连接测试】自动配置验证”事件，正文写明“这是自编连接测试，不是真实校园事件”，分类为“其他通知”，日期留空。有查询权限时，调用 list_notices，再用返回的完整编号调用 get_notice 核对原文；无结果时如实说明。不要仅生成 JSON。
5. 最后告诉我配置位置、连接结果、测试事件保存编号，以及当前会话是否需要重新加载或重启才能使用。

请区分“配置已写入”“连接验证成功”“当前会话已加载工具”，不要把它们当作同一件事。遇到失败请定位原因；缺少信息或确实需要我操作时，再明确说明。
```

### 安装并使用事件 skill

先连接好 MCP，再将 [skills/zhihui-notices](./skills/zhihui-notices/SKILL.md) 文件夹安装到所用 Agent 的技能目录；Codex 使用 `~/.codex/skills/zhihui-notices/`，其他客户端按自己的 Skill 安装方式。也可在面板“连接 Agent → 快速连接 → 下载 skill”获得 ZIP。压缩包根目录为 `zhihui-notices/`，不要只复制 SKILL.md，需保留 references 和 scripts。安装后重新加载技能或开启新会话，实际可用工具仍由 MCP 密钥和客户端白名单决定。

可直接说：“把这条事件和活动时间保存到知会”“找一下奖学金事件，给我材料要求”“最近有什么日程安排，做成时间轴”“我今晚有两小时，帮我安排比赛准备”。Codex 可显式使用 `$zhihui-notices`。

skill 会实时查询并按需读取原文；“最近”默认含今天的未来七天。完整日程会核对原文中的活动时间，不能只筛截止日期，避免漏掉没有报名截止的活动。报名截止和活动开始分成独立节点，缺失时分显示“时间未注明”，日期不可靠则单列待确认。时间轴是本地静态快照，包含来源、真实事件编号和日期依据，不代表用户已报名或已创建提醒；重新查询后可生成新版。

可视化脚本需要 Node.js 18 或以上，无 npm 依赖；无文件执行能力的 Agent 可按 skill 输出聊天时间轴或日期表格。工具参数及边界见 [Agent 接入说明](./AGENT_INTEGRATION.md)。

维护者可运行 `pwsh -NoProfile -File standalone/build-skill.ps1` 更新面板下载包及 `releases/zhihui-notices.zip`；构建 Windows 启动包时也会自动更新 skill 包。Skill 目录和打包产物不含密钥、账号和事件数据。

## 数据保存与旧版迁移

独立版默认将账号、密码哈希、会话、密钥哈希和事件保存在 `data/notice-inbox.sqlite`。源码方式运行时位于项目根目录，启动包方式运行时位于“知会本地版”根目录。本地运行时，数据在运行程序的这台电脑上；部署后，数据在服务器的持久存储中。原始密码和完整导入密钥不存入数据库。

- 网页“导入原文／导出原文”可迁移普通事件的 JSON 备份。包含课程和个人日程的完整数据库备份应先停止程序，再复制整个 `data` 目录。
- 旧版 JSON 备份可导入，重复事件会跳过，不覆盖已有内容。
- 原浏览器存在 `campus-notice-inbox.v1` 数据时，页面提供迁移入口，迁移不会清除原始数据。换站点地址后，通常需要从旧地址导出 JSON 再导入。
- 旧 OpenAI 登录账号与新邮箱账号不自动绑定，邮箱相同也不会自动取得旧账号的数据。

数据库、实际密钥和填写好的 `.env` 不应提交到公开代码仓库；项目已配置相关忽略规则。

## 源码结构

- `standalone/server.mjs`：独立版 HTTP 服务、页面与 API 入口。
- `standalone/auth.mjs`、`standalone/database.mjs`：账号、会话、导入密钥与 SQLite 数据库。
- `standalone/mcp.mjs`：独立版 MCP 工具与 Agent 导入。
- `standalone/agent-notices.mjs`：受账号隔离的查询、日期筛选、分页和原文读取。
- `standalone/categories.mjs`：按账号保存分类，重命名和删除时原子更新事件归类。
- `standalone/portable/`、`standalone/build-portable.ps1`：Windows 本地启动器、使用说明与打包脚本。
- `standalone/public/`：独立版登录与账号相关界面。
- `public/`、`app/panel.html`：共用事件面板脚本、样式与页面结构。
- `public/desktop.css`：独立版桌面阅读布局与字号优化。
- `skills/zhihui-notices/`：可分发的事件与时间规划 skill，以及本地时间轴生成器。
- `lib/notice-input.ts`、`lib/notice-store.ts`：共用输入校验与事件业务。
- `app/api/notices/route.ts`、`app/mcp/route.ts`、`db/schema.ts`、`drizzle/`：原 Sites 托管版接口与数据库结构。

事件原文以纯文本展示，来源链接仅允许 HTTP / HTTPS。服务端根据登录会话或导入密钥确定数据归属，不接收客户端指定的数据所属用户。

## 原 Sites 托管版开发

以下命令仅用于维护原托管版，不是独立邮箱版的启动步骤。要求 Node.js >= 22.13.0。

2026-10-20 的 `npm audit` 报告原托管版及开发工具链有 30 个受影响依赖包，其中 1 个严重、21 个高危；这些依赖尚未升级，使用此路径对外部署前应先修复并回归验证。独立邮箱版通过 Node.js 24 直接运行，不加载这套 npm 依赖。详见上传前检查记录。

```powershell
npm run install:ci
npm run db:generate
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_sparkling_frog_thor.sql
npm run dev -- --port 4173 --hostname 127.0.0.1
```

托管版与独立版默认使用同一端口，运行时应先停止另一版本。SQL 命令仅在新本地数据库执行一次，后续按生成的迁移顺序应用。托管版模板仅在本地模拟登录为开发用户，生产环境由 Sites 处理身份认证，线上和本地数据库相互独立。

托管版的额外检查：

```powershell
node node_modules/typescript/bin/tsc --noEmit
npm run build
```

Windows 若 npm 启动器错误地将自身安装路径识别为项目目录，可以用 `node "C:\Program Files\nodejs\node_modules\npm\bin\npm-cli.js"` 替代 `npm` 命令。
